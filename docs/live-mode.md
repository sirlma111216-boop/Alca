# 실시간 참여 — 학생이 각자 폰으로 들어오는 방식

**이 문서는 교사가 읽고 그대로 따라 할 수 있게 쓴 것입니다.** 개발 지식은 필요 없습니다.
(메시지 형식 같은 기술 내용은 [protocol.md](./protocol.md) 의 8절에 있습니다.)

---

## 1. 무엇인가

교사 화면에 **6자리 수업 코드**가 뜹니다.
학생이 자기 폰으로 그 코드를 넣고 들어오면, **모두가 똑같은 판**으로 벽돌깨기를 합니다.
점수가 교사 화면에 모이고, 그 점수로 **이번 발표자**가 정해집니다.

```
   교사 화면 (프로젝터)                  학생 폰 (각자)
   ┌────────────────────┐              ┌──────────┐ ┌──────────┐ ┌──────────┐
   │ 수업 코드  7K4M9P   │              │  벽돌깨기 │ │  벽돌깨기 │ │  벽돌깨기 │
   │ QR 코드            │   ◀── 참여 ── │  (같은 판)│ │  (같은 판)│ │  (같은 판)│
   │                    │              └────┬─────┘ └────┬─────┘ └────┬─────┘
   │ 들어온 사람 27명    │                   │            │            │
   │ 실시간 점수판       │   ◀── 점수 ───────┴────────────┴────────────┘
   │                    │
   │ ▶ 이번 발표자: 도윤 │
   └────────────────────┘
```

기존 방식과의 차이는 이것뿐입니다.

| | 기존 (단독 실행) | 실시간 참여 |
|---|---|---|
| 닉네임 입력 | 교사가 전원 분을 직접 입력 | 학생이 자기 폰에서 직접 |
| 게임 하는 곳 | 교사 기기 한 대 | 학생 폰 각자 |
| 걸리는 시간 | 직접 조작이면 사람 수 × 30초 | **전원이 동시에 30초** |
| 필요한 것 | 없음 (인터넷도 선택) | 인터넷 + 학생 폰 |

기존 세 가지 사용 방식(단독 실행 · iframe · npm 모듈)은 **그대로 남아 있습니다.**
실시간 참여는 거기에 더해진 **네 번째** 방식입니다.

## 2. 왜 점수를 학생 폰에서 계산하는가

**패들 조작을 서버로 왕복시키면 게임이 되지 않기 때문입니다.**

학생이 손가락을 움직이고 → 서버에 올라가고 → 서버가 공을 계산하고 → 다시 폰으로 내려오는
데는 학교 와이파이에서 보통 0.05~0.3초가 걸립니다. 공이 패들에 닿는 순간이 그만큼 어긋나면
"받았는데 안 받아졌다" 가 계속 일어납니다. 30초짜리 게임에서는 치명적입니다.

그래서 이렇게 만들었습니다.

- **전원이 같은 `seed` 를 받습니다.** seed 가 같으면 벽돌 배치·아이템 위치·공의 첫 각도가
  전부 같습니다. 즉 **모두가 똑같은 판**을 받습니다. (게임 엔진이 난수를 seed 하나로만
  만들도록 돼 있습니다 — [architecture.md](./architecture.md) 의 "결정성" 참고)
- 공의 물리 계산은 **각 폰이 스스로** 합니다. 지연이 아예 없습니다.
- 서버가 하는 일은 셋뿐입니다. **명단 세기 · 시작 신호 전달 · 점수 모으기.**
- 최종 순위와 발표자 선정은 **교사 화면**이 계산합니다. 서버가 아닙니다.
  기존 단독 실행 화면이 쓰는 것과 **완전히 같은 함수**(`computeRanking`, `selectPresenters`)를
  씁니다. 그래서 순위·동점 처리·제외 규칙이 기존과 한 치도 다르지 않습니다.

> **같은 경기장에서 서로 공을 주고받는 것이 아닙니다.**
> 각자 자기 경기장에서, 똑같이 생긴 판을 따로 깹니다.
> 다른 사람의 공이 내 화면에 들어오지 않습니다.

기기 성능 차이로 결과가 달라지지도 않습니다. 물리는 1/120초 고정 간격으로만 전진하고,
경기 시간을 벽시계가 아니라 **진행한 횟수**로 세기 때문에, 느린 폰에서는 실제 시간만
조금 길어지고 판 자체는 동일하게 흘러갑니다.

## 3. 수업에서 하는 순서

### 교사

1. 게임 주소를 엽니다 (예: `https://brickpick.sirlma.workers.dev`).
2. **[실시간 참여]** 를 고릅니다.
3. **[새 수업 열기]** 를 누릅니다. 6자리 코드와 QR 코드, 참여 주소가 뜹니다.
   - 코드는 **헷갈리는 글자(0 · O · 1 · I · L)를 빼고** 만듭니다. 불러 주기 쉽습니다.
   - 이 화면을 프로젝터에 그대로 띄워 두세요. **[주소 복사]** 로 주소만 따로 보낼 수도 있습니다.
4. 들어온 사람 수가 올라가는 것을 봅니다. 별명이 하나씩 나타납니다.
   **다 모일 때까지 기다립니다.**
5. 난이도 · 경기 시간(15/30/60초) · **선정 규칙**(1등 / 꼴찌 / 3위 / 상위 N명 …)을 정하고
   **[경기 시작 →]** 를 누릅니다.
6. 30초 동안 실시간 점수판을 봅니다. 누가 끝났고 누가 아직인지 보입니다.
   잘못 시작했으면 **[경기 취소]** 로 되돌릴 수 있습니다.
7. 전원이 끝나면 **[지금 집계하기 →]** 를 누릅니다. 순위와 **이번 발표자**가 나옵니다.
   같은 순간 학생 폰에도 결과가 뜹니다.
8. 필요하면 **[같은 학생들로 새 경기 →]** 로 한 판 더 합니다. 명단은 그대로 남습니다.
   기록을 남기려면 **[결과 JSON 내려받기]**, 수업을 마치려면 **[수업 끝내기]**.

> 수업 전에 혼자 연습해 보고 싶으면 **[데모 학생 넣기]** 로 가짜 참가자를 몇 명 넣어
> 전체 흐름을 돌려 볼 수 있습니다. 수업 시작 전에 **[데모 학생 빼기]** 로 꼭 지우세요.

### 학생

1. 교사 화면의 QR 을 찍거나, 주소를 치고 들어갑니다.
2. **수업 코드 6자리**를 넣습니다. (QR 로 들어왔으면 이미 채워져 있습니다.
   소문자로 쳐도 대문자로 바뀝니다.)
3. **화면에 보일 별명**을 정합니다. 12자까지. **실명을 쓰지 않아도 됩니다.**
4. **[참여하기]** 를 누르고 "선생님이 시작하면 바로 시작해요" 화면에서 기다립니다.
   이 화면에서 **[이름 바꾸기]** 로 별명을 고칠 수 있습니다.
5. 교사가 시작을 누르면 바로 게임이 뜹니다. **화면을 손가락으로 밀어** 패들을 움직입니다.
6. 끝나면 자기 점수가 나옵니다. 교사가 집계하면 발표자가 화면에 뜹니다.

> 늦게 들어온 학생은 그 판에는 못 들어가고 **다음 판부터** 참여합니다.
> 명단에는 바로 올라가므로 교사가 "아직 안 들어온 사람" 을 볼 수 있습니다.

## 4. 필요한 것

| 필요한 것 | 설명 |
|---|---|
| 인터넷 | 교사 기기와 학생 폰 모두. 학교 와이파이 또는 데이터 |
| 학생 기기 | 폰 또는 태블릿. 브라우저만 있으면 됩니다 |
| 교사 기기 | 프로젝터에 띄울 노트북·PC 한 대 |

**필요 없는 것**

- ❌ **계정 만들기** — 없습니다.
- ❌ **로그인** — 없습니다.
- ❌ **앱 설치** — 없습니다. 브라우저에서 주소만 엽니다.
- ❌ 학생 명단 미리 등록 — 없습니다. 학생이 들어오면서 자기 닉네임을 정합니다.

**인원**: 한 반 **최대 40명**입니다. 41번째 학생은 들어올 때 안내를 받고 거절됩니다.
40명이 넘는 수업은 두 번에 나눠 진행하세요(코드를 두 개 열면 됩니다).

## 5. 안 되는 경우와 대처

### 학교 와이파이가 막는 경우

학교 방화벽이 **WebSocket** 이라는 통신 방식을 막아 두면 학생이 들어오지 못합니다.
증상은 "참여" 를 눌러도 코드 입력 칸에서 넘어가지 않거나, 교사 화면에 참여 칸이 아예
나타나지 않는 것입니다.

| 확인 | 방법 |
|---|---|
| 게임 서버가 살아 있는가 | 브라우저 주소창에 `https://<게임주소>/api/health` 를 칩니다. `{"ok":true,"live":true, ...}` 가 보이면 서버는 정상입니다 |
| 우리 학교만 막힌 것인가 | 교사 기기에서 **휴대전화 데이터(핫스팟)** 로 바꿔 다시 해 봅니다. 되면 학교 망 문제입니다 |

**막혀 있을 때의 대처**

1. 학생들에게 **와이파이를 끄고 데이터로** 들어오게 합니다. (가장 빠른 해결)
2. 그래도 안 되면 **기존 단독 실행 방식**으로 진행하세요.
   교사가 닉네임을 붙여 넣고 자동 경기로 돌리면 됩니다 — 이 방식은 인터넷 상태와 무관합니다.
3. 정보 담당 선생님께는 "`brickpick` 주소에 대한 WebSocket(wss) 연결 허용" 을 요청하면 됩니다.

### 학생이 중간에 끊긴 경우

- **게임은 그대로 돌아갑니다.** 연결이 끊겨도 폰 안에서 계산되고 있기 때문입니다.
  화면에 "연결이 끊겼습니다" 가 뜨고, 점수 올리기만 잠시 멈춥니다.
- 브라우저가 **스스로 몇 번 다시 붙습니다.** 붙으면 점수가 따라잡힙니다.
- 계속 안 되면 학생이 **새로고침**합니다. 같은 폰이면 **같은 참가자로 돌아갑니다**
  (닉네임과 점수가 그대로 살아납니다).
- 끝까지 못 붙은 학생은 교사 화면에서 **흐리게, "끊김" 이라고 글자로** 표시됩니다.
  색깔로만 구분하지 않으므로 프로젝터에서도 읽힙니다.
- 그 학생의 점수가 안 올라왔다면 집계에서 **"기록 없음"** 으로 남습니다. **0점이 아닙니다.**
  발표자 후보에서는 빠지고 명단에는 남습니다.
  (0점으로 치면 "꼴찌 발표" 규칙에서 끊긴 학생이 뽑히는 사고가 납니다.)

### 교사 기기가 새로고침된 경우 (또는 실수로 창을 닫은 경우)

**당황하지 않아도 됩니다. 방은 서버에 남아 있습니다.**

1. 다시 게임 주소를 엽니다.
2. **[실시간 참여] → [최근에 연 수업]** 에서 조금 전 코드를 고릅니다.
   (직접 6자리를 쳐 넣어도 똑같습니다.)
3. 명단·점수가 그대로 돌아오고 **진행 권한도 되돌아옵니다.**
   경기 도중이었다면 그 경기 설정까지 서버에서 되받아 와 **이어서 집계**할 수 있습니다.

원래 교사 기기가 끊긴 상태라면 **다른 기기가 진행을 이어받을 수 있게** 해 두었습니다.
수업이 기기 하나 때문에 멈추면 안 되기 때문입니다.
(원래 교사가 아직 붙어 있는데 다른 기기가 진행을 가져가려 하면 거절됩니다.)

### 코드를 잃어버린 경우

교사 기기는 **자신이 연 최근 코드 5개**를 그 기기에 기억해 둡니다.
**[최근에 연 수업]** 목록에서 고르면 됩니다. 8일이 지난 것은 목록에서 사라집니다.
(그 기기에서만 보입니다 — 다른 기기에는 뜨지 않습니다.)

그 기기가 아예 바뀌었고 코드도 기억나지 않는다면 **찾을 방법이 없습니다.**
(누가 어떤 코드를 열었는지 서버가 기록하지 않기 때문입니다 — 계정이 없어서 그렇습니다.)
그럴 때는 새 코드를 열고 학생들에게 다시 들어오라고 하세요. 30초면 끝납니다.

### 그 밖에

| 증상 | 원인 | 대처 |
|---|---|---|
| 학생이 "수업을 찾을 수 없다" | 코드 오타 | `0`↔`O`, `1`↔`I`/`L` 은 애초에 코드에 안 씁니다. 다시 한 번 불러 주세요 |
| 41번째 학생이 못 들어옴 | 한 방 40명 제한 | 코드를 하나 더 열어 나눠 진행 |
| 시작을 눌렀는데 몇 명이 안 움직임 | 그 학생들이 아직 안 들어왔거나 끊김 | 명단에서 "끊김" 을 확인하고, 다시 들어온 뒤 한 판 더 돌립니다 |
| 소리가 안 남 | 브라우저 정책 — 사용자가 한 번 눌러야 소리가 납니다 | 학생이 화면을 한 번 누르면 납니다 |
| 8일 뒤 같은 코드로 들어가니 비어 있음 | 보관 기간이 지나 방이 정리됨 | 새 코드를 엽니다 |

## 6. 개인정보 — 서버에 무엇이 올라가는가

**올라가는 것**

- 학생이 스스로 정한 **닉네임** (12자까지)
- 그 판의 **점수·남은 목숨·깬 벽돌 수·진행률**
- 기기가 스스로 만든 **무작위 식별자** (이름과 아무 관계가 없습니다)

**올라가지 않는 것**

- ❌ **실명**
- ❌ **학번**
- ❌ **반 · 학년 · 학교 이름**
- ❌ 이메일 · 전화번호 · 로그인 정보 (애초에 계정이 없습니다)

서버도 **누가 누구인지 모릅니다.** 닉네임과 무작위 식별자만 들고 있습니다.
수업 코드는 URL 에 들어가지만 **닉네임은 절대 URL 에 넣지 않습니다**
(URL 은 브라우저 기록·리퍼러·서버 로그에 남기 때문입니다).

**보관 기간: 8일.** 마지막으로 쓴 지 8일이 지나면 방이 자동으로 비워집니다.
두 차시가 한 주 떨어져 있어도 같은 코드로 이어 쓸 수 있게 하려고 8일로 잡았습니다.

학생이 대기 화면에서 **나가기**를 누르면 **그 학생의 별명이 명단에서 바로 지워집니다.**
교사가 **[수업 끝내기]** 를 누르면 그 수업에서 손을 뗍니다(방은 8일까지 남아 있어
같은 코드로 다시 이어 쓸 수 있습니다).

> 학생에게는 "실명을 쓰지 않아도 된다" 고 미리 말해 주세요.
> 다만 교사가 누구인지 알아야 발표자를 부를 수 있으므로,
> **반에서 통하는 별명** 정도를 쓰게 하는 것이 실제로는 가장 편합니다.

## 7. 점수는 학생 폰에서 계산됩니다

**서버가 검증한 성적이 아닙니다.**

점수 계산이 학생 폰 안에서 끝나기 때문에, 브라우저 개발자 도구를 다룰 줄 아는 학생은
점수를 바꿔 올릴 수 있습니다. 서버는 올라온 숫자가 말이 되는 범위인지만 봅니다.

- ✅ **발표자를 정하는 용도로는 충분합니다.** 이 게임은 그 용도로 만들었습니다.
- ❌ **성적에 반영하지 마세요.** 수행평가 점수나 실력 측정으로 쓰면 안 됩니다.

자동 경기와 마찬가지로, 이 결과는 **게임으로 진행하는 추첨**에 가깝습니다.
학생에게 "게임 잘하는 사람이 발표" 라고 설명하지 마세요.
