# 예제 1 — 순수 HTML 호스트 (iframe + postMessage)

빌드 도구 없이 **HTML 한 장**으로 브릭픽을 붙여 보는 예제입니다.
브릭픽이 제공하는 도우미(`createBrickPickHost`)를 일부러 쓰지 않고 `postMessage` 를
손으로 주고받습니다 — 오가는 메시지를 눈으로 보면서 연동 규칙을 확인하기 위해서입니다.

실제 수업 앱을 만들 때는 이 파일을 그대로 베끼기보다,
`brickpick/host` 의 도우미를 쓰는 편이 짧고 안전합니다.
이 예제는 **그 도우미가 안에서 무슨 일을 하는지** 보여 주는 용도입니다.

---

## 1. 게임을 먼저 띄웁니다

저장소 루트에서:

```
npm install
npm run build:app
npm run serve:dist
```

`http://127.0.0.1:4178/embed/` 가 열리면 준비 완료입니다.

> 개발 중이라면 `npm run dev` (5173 포트)를 써도 됩니다.
> 그때는 아래 「게임 주소」 칸에 `http://localhost:5173` 을 넣으세요.

## 2. 이 예제를 띄웁니다

**파일을 더블클릭해서 열면 안 됩니다.** `file://` 로 열면 이 페이지의 출처(origin)가
`null` 이라 게임이 부모를 확인할 수 없어 연동이 끊깁니다. 화면에도 경고가 뜹니다.

간단한 서버로 여세요. 저장소에 들어 있는 정적 서버를 그대로 쓸 수 있습니다:

```
node scripts/static-server.mjs examples/html-host 4179
```

그다음 브라우저에서 `http://127.0.0.1:4179/` 로 들어갑니다.

## 3. 게임 쪽 허용 목록을 맞춥니다

브릭픽은 **허용된 부모 주소에서만** 열립니다.
로컬 개발 서버(`npm run dev`)는 `vite.config.ts` 가 이미 `localhost` 전체를 허용하므로
따로 할 일이 없습니다.

배포본(`npm run serve:dist`)으로 시험할 때는 `public/_headers` 의
`/embed/*` 규칙에 있는 개발용 주석을 잠깐 풀어야 할 수 있습니다.
그 파일에 방법이 적혀 있습니다. **운영 목록과 섞지 말고, 시험이 끝나면 다시 주석 처리하세요.**

---

## 무엇을 확인하나

화면 맨 위에 적힌 것이 이 예제의 존재 이유입니다.

> **여기서 넣은 참가자 ID 가 결과의 `selectedParticipantIds` 에 그대로 돌아오는지 확인하세요.**

게임은 참가자 ID 를 내부 번호로 바꾸지 않고 **받은 글자 그대로** 돌려줍니다.
학번처럼 수업 앱이 이미 쓰고 있는 값을 그대로 넣으면, 결과를 받아 바로 대조할 수 있습니다.
오른쪽 아래 **ID 왕복 확인** 칸이 보낸 명단과 돌아온 ID 를 자동으로 맞춰 봅니다.

그 밖에 이 화면에서 눈으로 확인할 수 있는 것:

- **메시지 순서** — `READY → INIT → INIT_ACK → START → PROGRESS… → COMPLETE → COMPLETE_ACK`
- **INIT 은 한 번뿐** — READY 가 여러 번 와도 INIT 을 다시 보내지 않습니다
- **검증 메시지** — 참가자 ID 를 일부러 중복시키면 `INIT_ACK` 가 거절 사유를 한국어로 돌려줍니다
- **제외 처리** — 「빼기」를 체크한 사람은 순위에는 남고 선정에서만 빠집니다
- **재전송 방어** — 같은 `resultId` 가 두 번 와도 결과는 한 번만 반영됩니다

---

## 연동 규칙 요약 (코드에서 지킨 것)

| 규칙 | 왜 |
| --- | --- |
| `message` 리스너를 **먼저** 붙이고 그다음 `iframe.src` 를 넣는다 | 순서를 바꾸면 `READY` 를 놓쳐 영영 멈춘 것처럼 보입니다 |
| `event.origin` 과 `event.source` 를 **둘 다** 확인한다 | 다른 창·다른 프레임이 보낸 메시지를 게임의 것으로 착각하지 않게 |
| `postMessage` 의 `targetOrigin` 에 정확한 주소를 적는다 (`'*'` 금지) | 게임이 다른 사이트로 바뀌어 있어도 데이터가 새지 않게 |
| 참가자·닉네임을 URL 쿼리에 넣지 않는다 | 주소는 기록에 남습니다. 명단은 `INIT` 메시지로만 보냅니다 |
| `COMPLETE` 를 받으면 즉시 `COMPLETE_ACK` 를 보낸다 | 답이 없으면 게임이 결과를 다시 보냅니다 |
| 같은 `resultId` 는 한 번만 반영한다 | 재전송분을 두 번 저장하지 않게 |

쿼리에 넣는 값은 `?parentOrigin=<이 페이지의 출처>` 하나뿐입니다.
게임이 "누가 나를 열었는가"를 알아야 답장을 보낼 수 있기 때문입니다.

## 자주 막히는 자리

**게임 화면이 하얗게/비어 보인다**
→ 게임의 iframe 허용 목록(`frame-ancestors`)에 이 페이지의 주소가 없습니다.
브라우저 개발자 도구 콘솔에 CSP 위반이 찍힙니다.

**아무 메시지도 안 온다**
→ 「게임 주소」의 포트가 실제로 뜬 서버와 다른 경우가 대부분입니다.
로그의 `⚙ 내부 열기` 줄에 실제로 연 주소가 찍히니 그 주소를 새 탭에서 직접 열어 보세요.

**`INIT_ACK` 가 accepted:false 로 온다**
→ 거절 사유가 `error.message` 에 한국어로 담겨 있고, 로그의 `상세` 줄에 항목별 원인이 나옵니다.
참가자 ID 중복, 후보보다 많은 인원 선정이 흔한 원인입니다.

**`file://` 경고가 뜬다**
→ 2번 항목을 다시 보세요. 반드시 `http://` 로 열어야 합니다.
